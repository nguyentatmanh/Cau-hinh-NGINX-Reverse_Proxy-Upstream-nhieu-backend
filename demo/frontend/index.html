2. Kết quả Phản hồi từ NGINX / Backend

Chưa gửi request. Hãy chọn file và bấm nút "Gửi Request Upload".

Quy trình thực hành Bước 5 (PDF):

  1. Gửi file 2.5 MB khi NGINX ở cấu hình mặc định (1m) → Nhận ngay HTTP 413 Payload Too Large từ NGINX.
  2. Sửa default.conf: thêm client_max_body_size 20m;.
  3. Chạy kiểm tra cú pháp: docker compose exec proxy nginx -t.
  4. Nạp nóng cấu hình: docker compose exec proxy nginx -s reload.
  5. Bấm gửi lại → Nhận HTTP 200 OK, ảnh lưu vào Shared Volume và hiển thị ngay lập tức!

2. Ý nghĩa Kỹ thuật & Cảnh báo Spoofing

Tại sao Peer IP lại là 172.x.x.x?

Trong kiến trúc Docker bridge network, kết nối TCP tới Backend xuất phát từ chính container NGINX, nên socket IP luôn là IP container NGINX. Đó là lý do bắt buộc phải cấu hình proxy_set_header X-Real-IP $remote_addr;.

Nguy cơ IP Spoofing & Quy tắc Trusted Proxies:

Kẻ tấn công có thể tự chèn X-Forwarded-For giả mạo. Backend chỉ được tin tưởng các header chuyển tiếp này khi request được gửi đến từ dải IP nội bộ đáng tin cậy của Reverse Proxy!
